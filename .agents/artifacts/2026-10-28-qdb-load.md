| 测试日期 | 2026-10-28 |

## 1. 采购方要确认的并发

并发按角色分开数，不能把订阅人数说成写入线程数。

| 角色 | 数量 | 在测什么 |
|---|---|---|
| 写入者 | **1** | 全库只有这一条写入路径。报价和成交都由它落盘 |
| 同时在读的订阅 | **128** | 写入进行中就已打开，每 1 毫秒读一次已落盘 WAL |
| 证券 | **32** | 沪市 16 只、深市 16 只。订阅按证券分担，多人可以盯同一只 |
| 测量笔数 | **20000** | 报价 10000 笔，成交 10000 笔。另外 2000 笔预热不计入延迟 |
| 重复 | **3 轮** | 每轮空库重来。汇总取成交 p99 居中的一轮 |

功能测试里还有两组，协议不同，不要和上表混成一个并发数：

| 协议 | 写入者 | 订阅 |
|---|---|---|
| 进程内只读打开 WAL | 1 | 256 个同时读，再加 1 个等写完再补的慢订阅 |
| WebSocket | 1 | 128 条连接只收 `SSE:600519`，另 1 条只收 `SZSE:000001` |

## 2. 指标定义

每一项先定义再给数。单位写在指标名后面。

| 编号 | 指标 | 定义 | 本次是否设采购门槛 |
|---|---|---|---|
| C1 | 写入者个数 | 测试期间调用 `write_trade` / `write_quote` 的线程数 | 设计值就是 1。实测 1 |
| C2 | 并发订阅数 | 测量全程存活、并在结束后补齐自家证券成交的只读方个数 | 本程序定为 128。全部补齐才算这项通过 |
| C3 | 订阅跟上率 | 补齐人数 / 128 | 门槛 100% |
| T1 | 测量墙钟 | 正式 20000 笔开始到最后一次 `flush` 结束的时间，不含预热 | 未设 |
| T2 | 混合吞吐 | 20000 / T1。报价和成交算在一起 | 未设。不能单独说成「成交笔/秒」 |
| L1 | 报价延迟 | 一次 `write_quote` 从调用到返回。p50 / p99 / p999 | 未设 |
| L2 | 成交延迟 | 一次 `write_trade` 从调用到返回。p50 / p99 / p999。批次在这一笔触发 `fsync` 时，刷盘时间算进这笔 | 未设 |
| D1 | 落盘次数 | 从 `open` 到本轮结束的 `fsync` 次数，含预热 | 未设 |
| F1 | 交易所隔离 | `SSE:000001` 与 `SZSE:000001` 不是同一只。裸代码 `000001` 必须失败 | 必须通过 |
| F2 | 已闭合 K 线 | 迟到成交可以进入逐笔和最新价，不得改已闭合秒的收盘价和成交量 | 必须通过 |
| F3 | 订阅隔离 | WebSocket 上，茅台的价不得出现在只订深市 `000001` 的连接里，反之亦然 | 必须通过 |

采购方如果要在招标文件里写性能条款，应事先写明 L2 的 p99 上限和 T2 的下限，并指定服务器、磁盘和是否带订阅。本次没有这些条款。

## 4. 性能实测

命令：

```bash
cargo run -p qdb-server --bin qdb-load --release --offline
```

三轮 C3 都是 128/128，进程退出码 0。居中轮是第 2 轮。

| 编号 | 指标 | 第 1 轮 | 第 2 轮（居中） | 第 3 轮 |
|---|---|---|---|---|
| C1 | 写入者 | 1 | 1 | 1 |
| C2 | 并发订阅 | 128 | 128 | 128 |
| C3 | 跟上 | 128/128 | 128/128 | 128/128 |
| T1 | 墙钟 | 71.9 s | 75.7 s | 80.9 s |
| T2 | 混合吞吐 | 278 笔/秒 | 264 笔/秒 | 247 笔/秒 |
| L1 | 报价 p50 | 36 µs | 39 µs | 39 µs |
| L1 | 报价 p99 | 3.07 ms | 3.14 ms | 3.23 ms |
| L1 | 报价 p999 | 139 ms | 100 ms | 138 ms |
| L2 | 成交 p50 | 1.53 ms | 0.97 ms | 0.98 ms |
| L2 | 成交 p99 | 180 ms | 195 ms | 202 ms |
| L2 | 成交 p999 | 355 ms | 381 ms | 404 ms |
| D1 | 落盘次数 | 5338 | 5163 | 5214 |

居中轮读法：128 个订阅都在读的时候，20000 笔用了 75.7 秒，混合吞吐 264 笔/秒。报价一半左右在 39 微秒内返回，是因为还留在 1 毫秒批次里。成交的 p99 是 195 毫秒，是因为批次经常先到 1 毫秒就 `fsync`，刷盘时间算在这笔成交上。落盘 5163 次，说明多数批次远没到 256 条。

## 5. 功能实测

| 编号 | 结果 | 证据 |
|---|---|---|
| F1 | 通过 | `a_broker_desk_opening_keeps_venues_apart_and_closed_bars_intact`。裸查 `000001` 失败；`SZSE:000001` 的价里没有沪市那只的 `99900` |
| F2 | 通过 | 同上。`SSE:600519` 已闭合秒收盘价保持 `16800700`，成交量不含迟到那一笔。只读再次打开后仍是这个收盘价 |
| F3 | 通过 | `many_websocket_subscribers_each_get_their_own_symbol`。128 条茅台连接收到 `16800700`，不收到 `120100`；深市那一条相反 |
| C3（功能规模） | 通过 | `many_desk_subscribers_catch_up_while_the_writer_keeps_going`。256 个只读订阅加上 1 个慢订阅，写完后写入者仍能再写 |

功能测试是 debug 构建下的对错判断，没有延迟分布。

## 6. 采购意见

功能项 F1、F2、F3 和「128 个订阅全部跟上」可以写入实验室记录。

性能项 T1、T2、L1、L2、D1 只能作为这台笔记本的实测，不能作为券商机房的验收值。成交 p99 约 200 毫秒。若采购文件要求开盘逐笔在毫秒内落盘，以本次环境不能给出「满足」的结论，需要在指定服务器上重跑同一条命令，并事先写明 p99 和吞吐门槛。

本报告不覆盖全市场路数、逐笔委托、十档订单簿、独立行情网和掉电。这些未测项不得写成已满足。
