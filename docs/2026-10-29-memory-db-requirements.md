# 内存数据库设计要求

本文是 QDB 作为内存数据库的要求。库只认表、列、主键、追加、最新值、分区键、`seq` 和订阅。调用方用这些能力装自己的数据。行情系统是用得比较多的一种场景，不进入模型，也不单列成一种表。

状态只有三种：

| 状态 | 含义 |
|---|---|
| 已实现 | 当前代码和手册里有 |
| 已设计 | 设计正文或分布式文档写了，代码还没有完成 |
| 不采纳 | 和本库的单写、全序或恢复方式冲突，不要实现 |

与 [`design.md`](design.md) 冲突时，以设计正文为准。本文不把未实现的接口写进手册。

## 1. 数据模型

本库的模型是带类型的行，不是文档库，也不是纯字节键值。键值是「一列主键的最新值表」。时序是「追加表加调用方写入的时间列」。宽表是普通的多列表。文档不解析；调用方若要存一段文本，把它放进 `STRING` 列，库不理解里面的结构。

| 要求 | 决定 | 状态 |
|---|---|---|
| 至少一种主流模型 | 行表：追加或按主键覆盖 | 已实现 |
| 主键查询 | 主键可多列，合起来唯一。等值查找走主键 | 已实现 |
| 范围查询 | 有序整型列上的比较和 `BETWEEN`。没有分区键约束时允许扫到上限后停止 | 已实现，扫描有上限 |
| 前缀查询 | `STRING` 前缀不作为索引能力。调用方需要前缀时用等值键或自己编码边界 | 不采纳为索引类型 |
| 版本 | 分区内 `seq` 严格加一。新的提交拿新序号。已发布的旧行不改序号 | 已实现 |
| 删除标记 | 不擦掉已 `fsync` 的行。调用方建成且带主键的表，用 `DELETE` 追加一条墓碑 `seq`，查询不再返回这个键。没有主键的表不能删。一次删除一个主键 | 已实现。批量删除仍未做 |
| TTL | 截止时间是调用方写入的 UTC 纳秒，0 表示没有期限。`EXPIRE AT` 用这个水位把到期的主键收成墓碑，不读本机时钟，也不擦 WAL。没有主键的表不参与 | 已实现 |
| 批量写 | 组提交：256 条或 1 毫秒，先到先刷 | 已实现 |
| 批量读 | 一次查询返回多行，受 `LIMIT` 和扫描上限约束 | 已实现 |
| 批量删除 | 单列主键可以 `DELETE ... WHERE 列 IN (...)`。每个值一条墓碑。有重复值或其中某个键不可见时，整句不写。复合主键仍是一次一个完整键 | 已实现 |
| 元数据与数据分离 | 表定义是单独的 WAL 记录。分区表、任期和成员属于控制面，不跟数据行混在同一条业务记录里 | 表定义已实现；分区表已设计 |

## 2. 性能要求

延迟按路径分开，不合成一个数。

| 要求 | 决定 | 状态 |
|---|---|---|
| 热点读在微秒到毫秒 | 同机读者读已经发布的共享内存，目标是微秒级。这是目标，不是验收合格线 | 路径已实现，未写成合格线 |
| 持久写入在毫秒级 | 先 `fsync` 再发布。1 毫秒先到时，延迟由刷盘决定。2026-10-28 笔记本单分区约 1423 行/秒，关闭批次的调用 p99 约 4.7 毫秒 | 已测量，仅该环境 |
| 单节点数万到数十万并发 | 连接数算在网关进程上，不算在写入进程上。写入进程保持一个分区一个写入线程 | 已设计 |
| 集群百万并发 | 多个网关水平扩展。每个分区只向网关推一份已发布流 | 已设计，未达到 |
| 读写隔离 | 写入线程不跑网络运行时。查询和订阅只读已发布的 `seq` | 已实现 |
| 负载突增不雪崩 | 队列有上限。满了只把该连接标成缺口，写入不等待。接入队列满时该分区记可见缺口，不静默丢、不把序号改小 | 订阅缺口已实现；分区接入缺口已设计 |

不要求写入延迟在刷盘变慢时仍然平坦。抖动要变成指标和缺口，而不是把写入线程堵住。

## 3. 分布式能力

| 要求 | 决定 | 状态 |
|---|---|---|
| 分片 | 按调用方分区键做范围分片。同一个键的全部行在一个分区 | 已设计 |
| 哈希或一致性哈希 | 16384 槽只负责把键路由到分区领导者。不把槽位重哈希当成在线搬迁历史的办法 | 路由已实现；自动搬迁不采纳 |
| 动态扩容 | 冻结父分区、记下最后已发布 `seq`、做快照、切成两个子分区。停顿期间拒绝新写入，停顿必须可见 | 已设计 |
| 缩容或移除节点 | 把领导权交给仍持有该分区副本的节点。不在线重排全部键 | 已设计 |
| 多副本 | 每个分区一个领导者、若干跟随者。复制 WAL，不复制共享内存 | 复制路径已实现；多分区路由未实现 |
| 发现、心跳、故障感知 | 哨兵询问、租约和 `leader_epoch`。没有任期的静态主备不能对外发布 | 询问和任期字段已实现；租约停写已设计 |
| 自动恢复 | 新任期从各副本已 `fsync` 的最大 `seq` 之后继续。落后的跟随者用 `from_seq` 或快照追上 | 已设计 |
| 路由不必广播 | 客户端缓存分区表和 `map_version`。版本不符再拉一次 | 已设计 |

共享内存不出节点。跨机器只复制 WAL 和状态快照。

## 4. 一致性模型

对外只承诺下面三档，不另造名字。

| 级别 | 含义 |
|---|---|
| D0 | 本机 `fsync` 后发布。只保证这台机器的盘 |
| D1 | 本机 `fsync` 后发布，副本异步拉取。缺省。尚未传到任何副本的尾部可以丢失 |
| D2 | 多数副本落入自己的 WAL 之后才对订阅者发布。没有副本时退回 D1 |

| 要求 | 决定 | 状态 |
|---|---|---|
| 写后读 | 发布之后，本机读者能看见该 `seq`。跟随者未追上时返回过期和自己的 `applied_seq` | 本机已实现；过期响应已设计 |
| 副本同步和追赶 | 跟随者按 `from_seq` 拉 WAL。有洞就停在洞前。落后超过保留时先装快照再续 | 已设计 |
| 延迟可见 | 每个副本的 `durable_seq` 差和 `applied_seq` 差要进指标 | 已设计 |
| 冲突写入 | 一个分区键只有一个写入者，不产生并发冲突。最新值表在这个写入者上后写覆盖。不提供多主合并 | 单写已实现；多主不采纳 |
| 元数据一致 | 分区表版本和 `leader_epoch` 单调。旧任期的 WAL 段被拒绝 | 已设计 |
| 排序 | 分区内用 `seq`。调用方时间只是列，不参与全序。没有跨分区的总序号 | 已实现 |

不提供跨分区事务，也不提供「所有分区同一瞬间」的全局快照。

## 5. 高可用与容灾

| 要求 | 决定 | 状态 |
|---|---|---|
| 数据面无单点 | 分区有跟随者。一台机器上仍只有一个进程持有写映射 | 跟随者已设计；单机写锁已实现 |
| 控制面无单点 | 哨兵多数。控制面只决定任期和分区表，不搬运每一行 | 已设计 |
| 故障切换 | 从连不上到投票有超时（缺省 200 毫秒量级）。恢复时间在演练前不写成已经达到的数 | 超时已实现；恢复时间未测量 |
| 多可用区 | 副本可以放在另一可用区，复制仍是 WAL。跨远距离只用于恢复，不当作同城实时读 | 已设计 |
| 持久化 | WAL 组提交加状态快照 | 已实现 |
| 重启恢复 | 快照加上其后的 WAL 重建内存。删掉共享内存文件后数据仍在 | 已实现 |

## 6. 存储与内存管理

| 要求 | 决定 | 状态 |
|---|---|---|
| 内存为主且不丢已发布数据 | 读者只看见已经 `fsync` 的 `seq`。共享内存可以整段丢掉，由 WAL 重建 | 已实现 |
| 淘汰 | 不用 LRU 或 LFU。热路径上按容量覆盖环形缓冲，慢读者得到缺口。追加段和 WAL 按保留期删除，删除前必须已有快照能恢复 | 环形缓冲和 WAL 保留已实现；LRU/LFU 不采纳 |
| 预分配和定长 | 区域创建时定长。帧 256 字节。热路径不放 `Vec`、`String`、`HashMap` 进共享内存 | 已实现 |
| 零拷贝 | 共享内存里按槽读固定帧。默认库接口拷贝出 256 字节再交给调用方 | 已实现 |
| 压缩 | 环形缓冲和热路径帧不压缩。冷段以后可以压缩，不改变 `seq` | 热路径不采纳；冷段已设计为以后 |
| 冷热分层 | 热数据在内存和共享内存。冷数据是已密封段下沉，查询接口以后与热数据相同 | 热路径已实现；冷数据未实现 |

## 7. 查询与索引

| 要求 | 决定 | 状态 |
|---|---|---|
| 主键精确查询 | 主键等值 | 已实现 |
| 低延迟范围查询 | 分区键或有序列上的范围。先定位分区，再在区内扫描 | 单机扫描已实现；先定位分区已设计 |
| 二级索引 | 单列、非唯一、等值。没有索引的过滤可以扫表，扫到上限停止 | 已实现 |
| 分页 | `LIMIT`。订阅用 `from_seq` 做游标。不用大偏移翻页 | 已实现 |
| 流式返回 | 订阅在当前结果之后持续给新行 | 已实现 |
| 聚合 | 单列 `COUNT`、`SUM`、`MIN`、`MAX`、`AVG`、`FIRST`、`LAST` | 已实现 |
| 避免全表扫描 | 分区键写在最外层合取条件上时下推。没有分区键的查询可以扫到上限，不保证使用索引 | 部分已实现 |

不承诺任意条件都走索引。

## 8. 事务与并发控制

| 要求 | 决定 | 状态 |
|---|---|---|
| 单键原子 | 一次提交分配一个 `seq`，其中的行一起发布。读者不会看见半组 | 已实现 |
| 多键事务 | 同一个分区、同一条提交里的多行可以一起发布。跨分区不提供事务 | 单分区已实现；跨分区不采纳 |
| 乐观锁或条件写 | `INSERT ... EXPECT n`。`n` 为 0 表示键必须不存在；大于 0 必须等于该主键当前可见 `seq`，然后覆盖。不符不写 | 已实现 |
| 脏读 | 未 `fsync` 的 `seq` 不发布 | 已实现 |
| 丢失更新 | 一个分区键只有一个写入者。条件写用来挡住调用方自己的重试 | 已实现 |
| 长事务 | 不提供会占住写入线程的长事务。组提交只聚合短写入 | 不采纳 |

## 9. 网络与协议

| 要求 | 决定 | 状态 |
|---|---|---|
| 二进制协议 | 共享内存帧和 TCP 长度前缀帧是二进制。热路径帧不经过通用序列化 | 帧已实现；TCP 订阅已设计 |
| 长连接和流式 | 订阅连接先给当前结果，再给新行 | WebSocket 已实现 |
| 批量请求 | 组提交一批行。查询一次返回多行 | 已实现 |
| 鉴权、限流、超时、重试 | 做在网关。写入线程不鉴权。超时和重试不能让写入者等待慢客户端 | 已设计 |
| TLS | 做在网关到终端的连接上。节点内部复制不在本文规定套哪一种证书 | 已设计 |
| 版本兼容 | 帧布局用 `abi_version`。改帧头、槽位或 seqlock 规则才加一。组提交间隔不是布局 | 已实现 |

当前还提供 JSON 的 HTTP 和 WebSocket。那是控制面和文本订阅，不是热路径帧。

## 10. 可观测性

| 要求 | 决定 | 状态 |
|---|---|---|
| 延迟、吞吐、错误、连接、队列 | `/metrics` 至少有序号、缺口、心跳、订阅连接数。组提交耗时和每秒接受行数按分区暴露 | 单机指标已实现；分区指标已设计 |
| 慢查询 | 查询日志缺省关闭。打开后只记超过配置的语句，不把每行订阅打进日志 | 已设计 |
| 异常日志 | 恢复结果、缺口、损坏的 WAL 用结构化日志 | 已实现 |
| 审计 | 订阅建立和断开要能记。完整审计文件以后再加，不在写入热路径 | 部分已实现 |
| 拓扑、副本、分片 | 分区表版本、任期、每个副本的序号差 | 已设计 |
| 告警 | 库暴露指标。节点不可用、副本落后、WAL 损坏由外部根据指标告警，库内不内置告警通道 | 指标已实现；告警通道不采纳 |
| 诊断 | `/health` 反映本进程能否服务。热点和阻塞看分区队列和组提交耗时，不另做内存泄漏扫描器 | 健康检查已实现 |

## 11. 运维与治理

| 要求 | 决定 | 状态 |
|---|---|---|
| 初始化 | 一个数据目录、一把实例锁、一份 WAL | 已实现 |
| 扩容、缩容、替换节点 | 按第 3 节的分区切开和任期切换。替换是把领导权交给已追上的副本 | 已设计 |
| 配置热更新 | 组提交条数和间隔可以改，不改 `abi_version`。改帧布局必须重启并换版本 | 间隔已实现为配置 |
| 备份与恢复 | 状态快照加 WAL。恢复后的 `seq` 和行必须与备份点之后的日志一致，并有可重复的检查 | 单机恢复已实现 |
| 灰度与滚动升级 | 同一 `abi_version` 的节点可以按分区滚动替换。布局不兼容时先整分区停写，再换 | 已设计 |
| 权限、租户、配额 | 第一版只有操作系统文件权限。账号、租户和配额做在网关，不做到分区写入线程里 | 文件权限已实现；其余已设计 |
| 访问审计 | 见第 10 节。查询审计缺省不打开 | 已设计 |

## 12. 不因本清单改口的约束

- 一个分区键一个写入者。不把多个线程放到同一份 WAL 上。
- 已发布的 `seq` 已经 `fsync`。
- 数值用 `i64`。热路径不用浮点。
- `unsafe` 只在共享内存和 WAL 两处。
- 库不解释列的含义。调用方的表不是引擎类型。
