# 数据模型

## 证券

证券在第一次 `write_trade`、`write_quote` 或 `upsert_symbol` 时注册。内部 `symbol_id` 从 1 递增，进程重启后由 WAL 重放恢复，不重新编号。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `u32` | 内部编号，从 1 起 |
| `exchange_id` | `u16` | 标签第一次出现时分配，从 1 起 |
| `exchange` | 字符串 | 调用方标签。WAL 只保留前 16 字节 |
| `code` | 字符串 | 证券代码。WAL 只保留前 32 字节 |
| `price_scale` | `u16` | 当前恒为 10000，不参与计算 |

键是 `(exchange_id, code)`。同一标签下重复注册同一个代码会返回已有编号。

## 成交

`ticks` 按证券追加，不覆盖。

| 字段 | 类型 | 说明 |
|---|---|---|
| `seq` | `u64` | 分配给这笔成交的序号 |
| `ts` | `i64` | 调用方传入的 UTC 纳秒 |
| `price` | `i64` | 成交价 |
| `volume` | `i64` | 成交量 |
| `amount` | `i64` | `price * volume`，溢出时饱和 |

`trade_id` 在当前写入路径里固定为 0。

时间早于该证券当前未闭合桶起点的成交不进入 K 线，并计入 `late_tick_total`。这笔成交仍然写入 `ticks`。

## 报价

每个证券保留最新一条报价。

| 字段 | 类型 | 说明 |
|---|---|---|
| `seq` | `u64` | 产生这条报价的序号 |
| `last` | `i64` | 最新价 |
| `bid_px` | `[i64; 5]` | 买价。`write_quote` 只填写第 1 档 |
| `ask_px` | `[i64; 5]` | 卖价。`write_quote` 只填写第 1 档 |

成交也会把 `last` 更新为成交价，不清买价和卖价，也不把成交量累进 K 线以外的报价字段。报价不改变 K 线的 OHLC 和成交量。

`TickQuote` 结构体还有五档数量和成交累计字段。经过 `Engine::write_quote` 时，WAL 只保存 `last`、买一价和卖一价。

## K 线

每个证券、每个周期最多一条未闭合 K 线。闭合后追加到该周期的序列，不覆盖已闭合记录。

| 周期 | SQL 名称 | `period_id` | 桶长 |
|---|---|---|---|
| 1 秒 | `1s` | 1 | 1 秒 |
| 1 分 | `1m` | 60 | 60 秒 |
| 5 分 | `5m` | 300 | 300 秒 |
| 15 分 | `15m` | 900 | 900 秒 |
| 1 时 | `1h` | 3600 | 3600 秒 |
| 4 时 | `4h` | 14400 | 14400 秒 |
| 1 日 | `1d` | 65535 | 86400 秒 |

日线的编号是 `u16::MAX`，因为 86400 放不进帧头里的 `u16`。

一笔成交会同时更新全部 7 个周期。桶起点是不大于事件时间的 UTC 边界。进入新桶时，旧桶闭合，新桶以这笔成交作为开高低收。

未闭合 K 线的 `state` 为 0，闭合后为 1。`origin` 当前为 0，表示实时写入。

## 逻辑表

SQL 能读四张表。它们是内存视图，没有独立的建表语句。

| 表 | 一行是什么 | 必需过滤 |
|---|---|---|
| `symbols` | 一只证券 | 无 |
| `ticks` | 一笔成交 | `symbol` |
| `snapshots` | 一只证券的最新报价 | `symbol` |
| `klines` | 一根 K 线，含未闭合的最后一根 | `symbol` 和 `period` |

`klines` 先返回已闭合的桶，再附上当前未闭合桶。
