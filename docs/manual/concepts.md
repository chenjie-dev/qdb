# 概念

## 单写多读

一个进程负责分配序号、写 WAL、改内存表、发布共享内存。读者只读映射 `region.bin`，或在同一进程里调用查询和订阅。读者落后时得到明确的套圈或缺口，不会读到半帧后继续当作连续行情。

写入顺序固定为：

```text
分配 seq → WAL fsync → 更新内存 → 发布触发帧
```

当前每一笔库接口写入都 `fsync` 一次。`qdb` 进程另有组提交：256 条或 1 毫秒到齐就刷一次盘，见 [服务进程](server.md)。

## 序号

`seq` 从 1 开始，在这一个库里连续递增。成交、报价、代码注册和时钟各占一个序号。由这笔输入派生出的 K 线帧带同一个序号，单独不再分配新序号。

读者用最后收到的 `seq` 作为 `from_seq` 来续传。缺号必须显式处理，不能把后面的帧接成连续序列。

三个对外可见的序号：

| 名称 | 含义 |
|---|---|
| `durable_seq` | 已经 `fsync` 的序号 |
| `applied_seq` | 已经应用到内存表的序号 |
| `write_seq` | 已经发布到环形缓冲的序号 |

当前实现里，一次 `write_*` 返回时这三个值相同。

## 时钟

所有时间戳都是 UTC 纳秒。K 线桶按 UTC 对齐：

```text
bucket_start = event_ts_ns - event_ts_ns.rem_euclid(period)
```

日线桶长 86400 秒，从 UTC 00:00:00 起算。业务系统若要按上海、香港或纽约的交易日切日线，先把本地时间换成对应的 UTC 时间再写入。

没有成交时，桶不会自己关闭。业务系统在需要收线时调用 `write_clock`，传入该交易所标识和 UTC 水位。水位大于等于桶的结束时间时，该标识下仍开着的桶会闭合。

## 交易所标识

交易所代码是调用方给出的标签，例如 `"SSE"`、`"SZSE"`、`"HKEX"`、`"NASDAQ"`、`"BINANCE"`。库在第一次见到某个标签时分配内部 `u16` 编号，之后原样保存，不解释开市时间、时区、夏令时、复权或涨跌停。

空字符串会被拒绝。写入 WAL 时，标签保留前 16 字节，代码保留前 32 字节。调用方应在传入前控制长度；超长的代码恢复后会变成截断值。

对外引用一只证券用 `交易所:代码`，例如 `SSE:600000`。只写代码时，库里必须恰好有一只同名证券，否则查询和订阅返回歧义错误。

## 价格和数量

价格、数量、金额都是 `i64`。库不做浮点运算。成交金额为 `price.saturating_mul(volume)`。

内存里的 `price_scale` 当前固定写成 10000，不参与换算。调用方要自己决定 1050000 代表 105.0000 还是别的刻度。

## 帧

跨进程的消息是 256 字节定长帧：48 字节头，208 字节载荷。魔数 `0x51444231`，ABI 版本 1。只支持小端主机。

| `msg_type` | 名称 | 谁产生 |
|---|---|---|
| 1 | `TickTrade` | `write_trade` |
| 2 | `TickQuote` | `write_quote` |
| 3 | `KlineUpdate` | 成交更新未闭合 K 线 |
| 4 | `KlineClose` | 下一桶或时钟闭合 K 线 |
| 5 | `SymbolUpsert` | 第一次见到证券 |
| 6 | `ClockTick` | `write_clock` |
| 7 | `GapAck` | 类型已保留，`Engine` 当前不写入 |

共享内存只发布触发写入的那一帧。K 线帧留在进程内的帧列表里，供订阅读取。
