# 券商级行情内存库：尚未覆盖的能力

本文列出 QDB 要成为企业级、能适配券商行情要求时还缺的能力。[`docs/design.md`](design.md) 的 M1–M5 和币安式连续交易仍然有效。这里的每一项都 **尚未实现**，任务没有点名时不要提前做。

行情库继续只保存和分发行情。下单、撤单、风控裁决、清算交收不进这个库。库要给这些系统提供稳定、可追溯的行情。

## 1. 已经有的，不要重复设计

单写多读共享内存、本地 `seq`、缺口可见、五档快照、成交驱动的多周期 K 线、已闭合不覆盖、WAL 与启动恢复、基础 SQL、按代码和周期续传、A 股交易日、`BINANCE` 的 UTC 日线和时钟收线。原始价入库，复权因子不写进 K 线。

## 2. 品种

现在只有沪深京股票代码形态和币安现货代码。券商柜台至少还要：

| 品种 | 还缺什么 |
|---|---|
| A 股股票、存托凭证 | 上市、退市、代码变更、ST、停牌、临停、退市整理期 |
| 基金、ETF、LOF、REITs | IOPV、净值、申赎状态；ETF 与成分股不是同一条行情 |
| 可转债 | 转股价、转股期；交易单位和涨跌幅与股票不同 |
| 指数 | 点位和样本调整。指数没有可成交的五档 |
| 股票期权 | 合约链：标的、到期日、行权价、认购认沽。询价单独一条消息 |
| 商品期货、金融期货、国债期货 | 夜盘、集合竞价、持仓量、结算价。结算价不是收盘价 |
| 商品期权、金融期权 | 与标的、与同到期合约的关联 |
| 组合与套利合约 | 价差行情，不把两条腿偷偷合成一根 K 线 |
| 港股通、沪深股通 | 额度、标的可买可卖状态、港股收市竞价与开市前时段 |
| 港股、美股、其他境外股票 | 盘前、盘中、盘后；夏令时；碎股和暗盘与正常交易分开 |
| 主力连续与加权合约 | 映射表。换月日不改写已经闭合的真实合约 K 线 |

每个品种有自己的最小变动价位、申报单位、涨跌幅规则和交易日历。这些是资料，不写死在聚合分支里。

## 3. 消息类型

现在只有成交、五档报价、K 线、符号登记、时钟水位和缺口确认。券商行情还要能原样收下并按序号重放：

- **逐笔委托**：新单、撤单、改单。委托号在同一交易所通道内可追踪。
- **逐笔成交**：成交编号、买卖双方委托号、主动方向。成交可以撤销（bust），撤销是新事件，不抹掉原成交。
- **委托队列**：买一卖一上的前若干笔委托数量。
- **集合竞价不平衡**：虚拟参考价、未匹配量、匹配量。竞价阶段的价不提前写成连续竞价成交。
- **交易状态**：开盘前、开盘竞价、连续竞价、收盘竞价、休市、闭市、停牌、熔断、盘后固定价格、夜盘。状态变化本身占用 `seq`。
- **盘口档位**：沪深 Level-2 常见十档，期货常见五档，境外市场档数不固定。五档是第一版帧的上限，更深的档位用续帧，截断必须计数。
- **持仓量**：期货和期权的未平仓量，跟成交量分开。
- **结算价、昨结算、昨收、今开**：涨跌幅的基准由品种决定。期货用昨结算，股票用昨收。
- **大宗、盘后、协商成交**：与连续竞价成交分类型。是否进入日线由品种规则决定，默认不混进连续竞价 K 线，除非资料明确要求。
- **24 小时滚动统计**：最新价、窗口高低、成交量和额。窗口随当前时刻滑动，不是 `1d` K 线。

交易所通道序号和 QDB 的 `seq` 继续是两个数。通道序号用于发现上游断线；`seq` 只由本库写入者分配。

## 4. 订单簿

五档快照不够重建盘口。后续要有两种簿，都由逐笔委托和逐笔成交推导：

- **按价聚合**：每个价位的总量和笔数。
- **按委托**：每个委托号的剩余量，用于排队和撤单。

簿的更新与成交使用同一条已落盘的 `seq`。快照加增量的规则与现在的订阅相同：断档或落后太多时先发簿的快照，再发比快照新的增量。快照的更新号接不上时，标记缺口并重新建簿，不用猜测把洞补上。

买卖价交叉（买价高于卖价）要打标，不在库里改价格。

## 5. 日历和时段

现在只区分上海交易日和 UTC 自然日，空窗检测写了 A 股白天两段。后续每个交易所一份日历：

- 节假日、半日市、临时休市。日历可以在不重启写入者的情况下换版本，已闭合 K 线不因新日历改写。
- 期货夜盘跨自然日。夜盘属于下一个交易日，不拆成两根日线。
- 港股开市前时段和收市竞价，美股盘前盘后。这些时段的成交带时段标记。
- 夏令时按交易所时区规则计算，不写死偏移分钟数。`BINANCE` 保持 UTC，没有夏令时。
- 停牌期间没有成交是正常状态，不是缺口。连续交易市场的安静也不是休市。

## 6. 证券资料和公司行为

行情流里的代码要能对上每日静态文件（证券信息、涨跌停价、交易单位、标的状态）。资料变更写入 WAL，和行情共用 `seq`，这样重放后状态一致。

公司行为：

- 分红、送转、配股、拆并股产生复权因子。因子按生效日版本化。
- 查询可以要求不复权、前复权、后复权。计算发生在读路径，K 线里的原始价不变。
- 因子版本写进查询结果。没有因子时返回原始价并标明，不用 1 假装已经复权。
- 合约到期、换月、代码变更：旧代码的历史仍可查，新代码不继承旧 `seq`。

财务指标、股本、市盈率需要另来的参考数据。没有这份数据时，不在行情库里算这些比率。

## 7. 券商行情里常见的派生字段

这些由已落盘的成交和盘口算出，算法版本要记在结果上：

- 涨跌、涨跌幅、振幅。基准见第 3 节。
- 均价（成交额 / 成交量），分时图用它。
- 内外盘、委比、委差、量比。
- 当日累计成交量和额，与单笔成交分开。
- VWAP。TWAP 若需要，用成交时间而不是到达时间。
- 期货增仓、减仓方向只在同时有成交量和持仓量变化时计算，缺持仓量就不算。

派生字段可以随新成交更新。已闭合 K 线的 OHLC 仍然只追加修订版。

## 8. 多源和数据质量

券商机房通常有主备两条行情线，还有多家供应商。后续：

- 同一分区仍只有一个写入者。主备源在写入者前面仲裁，不把两条线都写成 `seq`。
- 仲裁规则要可配置：先到先用，或指定主源、备源只补洞。切换本身写成 WAL 事件。
- 上游通道缺号时，向该源请求重传；重传回来的事件仍按原通道序号去重，再分配新的本地 `seq`。
- 价格、量、时间戳异常打标：负价格、买卖价交叉、事件时间大幅偏离接收时间、涨跌停以外的成交。默认不改数值。过滤策略是显式配置，被丢掉的事件要计数。
- 时钟按证券期货业的同步要求对齐。接收时间使用同步后的时钟。硬件时间戳可以后加，没有时不编造。

## 9. 接入

现在没有交易所或供应商适配器。后续每种源一个适配器，输出同一种内部事件，不把协议字段散落到聚合器里。

优先覆盖券商实际在用的源：

| 源 | 典型内容 |
|---|---|
| 上交所二进制 / STEP、深交所二进制 | A 股现货与期权的快照、逐笔 |
| 中金所、上期所、大商所、郑商所、能源中心、广期所及 CTP 一类接口 | 期货快照、持仓、结算 |
| 港交所、美股行情源 | 盘前盘后和多档 |
| 币安现货与合约 WebSocket | 已经在模型里预留的连续交易 |
| 组播 UDP | 机房内行情分发。丢包用通道序号发现，再用重传或备源补 |
| 恒生、金证、通达信、万得一类终端或柜台行情 | 作为下游协议，不作为库内存储格式 |

适配器崩溃不能留下半条已发布的 `seq`。它和写入者之间仍是单消费者队列，序号在写入者线程上分配。

## 10. 分发、权限和延迟档

现在本机信任连接，文件权限只靠操作系统。券商要按人和用途分发行情：

- 账号至少区分查询、订阅、运维。仍然没有远程写入共享内存的角色。
- **实时** 和 **延迟** 是两档授权。延迟档只能读到当前时间减去授权延迟之后的 `seq`，不能先拿到实时再在客户端睡觉。
- Level-1 与 Level-2、展示与非展示，按交易所授权截断档位和字段。未授权的字段不出现在结果里。
- 订阅除了单码和周期，还要支持自选列表、板块、全市场某品种。全市场推送必须能背压：慢客户端被标成缺口，不拖住写入。
- 机构接口至少留出 FIX 行情（快照、增量、拒绝）和现有的 WebSocket、gRPC 计划。柜台私有协议做成适配层。
- 每个订阅和每次越权拒绝写入审计。查询审计可按比例采样，采样率要能改。
- 单连接和单账号限流。超限返回明确错误。

## 11. 历史和容量

现在 Tick 只保证短窗口内存，WAL 保留以天计。券商研究、回测和监管调阅要：

- 当日全市场逐笔留在热数据。更早的逐笔和 K 线进冷存储，查询接口相同。
- 冷存储按符号、周期、日期分段，只追加。修复用新修订版，不改旧文件字节。
- K 线历史按品种默认覆盖多年日线和足够的分钟线。具体年限做成配置。
- 全市场峰值按每秒百万级事件设计分区和批量落盘。做不到这个量级时，指标要暴露写入排队，而不是静默丢弃。
- 历史导入已经在设计第 9.4 节预定，实现时要能灌入静态收盘文件和逐笔归档。

## 12. 可用性

分区、复制、任期切换和单机并行见 [分布式、高可用与高并发](2026-10-19-distributed-ha.md)。异地灾备只做恢复，不把远距离复制当成同城实时读。在没有演练数字之前，不写已经达到的恢复时间。

## 13. 运维和监管留痕

在现有健康检查之上增加：

- 按源、按通道的最后序号、缺口、重传次数、主备切换次数、事件时间与接收时间之差。
- 盘前检查：静态资料已加载、日历覆盖当日、主源有心跳。没过检查就不对外宣布实时行情可用。
- 盘后核对：收盘价、成交量与交易所收盘文件或结算文件比对，差异写成报告，不自动改 K 线。
- 行情留痕保留期按交易所和监管要求配置，到期前不能删掉被审计引用的分段。
- 谁在何时订阅了哪只实时行情，要能查到。

## 14. 后续实现顺序

做的时候仍走 `qdb-pipeline`，并先改设计正文里相应的节。建议顺序：

1. 证券资料、交易日历、交易状态、十档、昨收或昨结算、涨跌幅。
2. 逐笔委托和按价订单簿，主备源仲裁。
3. 期货夜盘、持仓量、结算价；期权合约链。
4. 复权查询、冷热历史、盘后核对。
5. 实时与延迟授权、Level-2 截断、审计、限流。
6. 同城复制的可测切换。港股和美股时段、FIX 与组播放在对应市场开做时一起加。

每一项完成前，查询和订阅都要能看出数据是原始实时、延迟档，还是复权计算结果。
